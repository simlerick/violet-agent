# Violet Agent — 安全白皮书（Security Model）

> 本项目托管真实资产，**安全是上线前提而非加分项**。子母钱包架构本身就是安全设计的一环。

## 设计原则

### 1. 私钥永不上云
- 助记词**本地生成**（BIP39），私钥本地用 **Argon2id** 派生密钥 + **XChaCha20** 加密落盘
- 加密口令由用户自设，**绝不发送到任何服务器**
- 私钥/助记词仅由本地钱包组件（Rust）使用

### 2. 子母钱包主权分离（核心）
- **母钱包**：资金主权与调度权永远在主人手里，不参与每笔交易签名
- **子钱包**：Violet 只持有执行权限；即便被攻破，损失上限 = 子钱包余额
- **可撤权**：主人随时终止子钱包权限、回收资金

### 3. 交易确认分级
- **子钱包自动执行**（100% 使用权，风控边界内）
- **母钱包级操作需主人签名确认**：大额转账、更换绑定、撤权

### 4. 三层风控硬编码
- 单笔限额、日累计限额、滑点上限——**写死在本地，LLM 无权覆盖**

### 5. 最小权限
- RPC / API Key 只给只读或限额授权
- 签名用本地钱包，而非托管 API

### 6. 可审计
- 每笔交易、每次授权/撤权全链路留痕，便于开源社区审计

### 7. 开源透明
- 代码开源，安全机制可被审查，而非黑箱

## 攻击面 & 缓解

| 威胁 | 缓解 |
|---|---|
| 子钱包私钥泄露 | 损失上限 = 子钱包余额；母钱包主权隔离 + 可撤权回收 |
| 母钱包助记词泄露（最致命） | 本地生成、本地加密、口令保护、冷钱包导入选项 |
| AI 误下单（LLM 理解偏差） | 子钱包限额 + 可撤销 + 风控硬编码 |
| 恶意 DApp / 合约 | 白名单 DApp + 只走成熟协议 |
| 供应链攻击（依赖） | 锁定依赖版本、CI 校验、审计文档 |
